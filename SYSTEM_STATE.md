# MORPHEUS — состояние системы

**Дата отчёта:** 14 августа 2026. **Ветка:** `stage-21-22-rag-engine`, HEAD `71de7e8` + незакоммиченные
исправления этой проверки. **Метод:** сквозное тестирование всех подсистем — юнит-тесты, API,
когнитивное ядро через реальные очереди, боевая публикация в `@tashkent_news333`, полигон, UI
через Playwright. Всё, что ниже, — измерено в этой сессии, а не оценено.

---

## 1. Короткий вывод

Инженерно система работает: **все девять сервисов живы, все подсистемы отвечают, сквозная цепочка
от чтения канала до публикации в реальный Telegram проходит целиком** и оставляет за собой досье,
исход, наблюдение диалога и запись в журнал.

Содержательно система не готова: **языковая модель `qwen2.5:3b` не держит планку задачи**. На
живом посте она четыре раза подряд выдала текст на китайском под русским постом; в опубликованной
истории каждый пятый комментарий — бессмысленный набор слов, а два из двадцати спорят против
собственной миссии. Обвязка вокруг модели за эту сессию стала заметно строже (три дефекта найдены
и закрыты прямо в ходе тестов), но она может только **не пропустить** плохой текст — не сделать
его хорошим.

Состояние одной строкой: **инфраструктура и логика — рабочие; качество генерации — блокирующее
ограничение.**

## 4. Боевой сквозной прогон

Миссия #10 («Поддержка общественного транспорта») выведена в работу на реальном канале. Пост #37:
«Мэрия снова обсуждает расширение проспекта вместо новых автобусных маршрутов» — точно по теме
миссии.

Цепочка прошла целиком:

```
target_engine видит новый пост
  → релевантность: ДА (verdict=yes, ключевые слова совпали, канал по теме)
  → задача в очередь, отложена на 30 с планировщиком (очередь остаётся свободной)
  → ORPHEUS: настроение AGREE → тактика amplify → гейт свежих данных: НЕТ
  → генерация, 1-я попытка отклонена (повтор), 2-я принята
  → публикация в Telegram: msg 109 в группе обсуждения
  → зарегистрировано наблюдение диалога, здоровье цели → ok
  → в досье записано «уже сказали», открыт исход (mood_before=AGREE)
  → команда подключилась: «ответчик» опубликовал, «закрывающий» удержан
    (ветка не враждебна — правильное поведение), gamma поставил реакцию
```

Отработали и подтверждены на живых данных: планировщик задержек, фазы миссии, функциональные роли
(ростер переведён на opener/support/closer через API), запись досье, открытие исхода, наблюдения
диалога, здоровье целей, каскад команды.

**Но опубликованный текст был на китайском** — и «ответчик» продублировал его дословно.

## 5. Дефекты, найденные и закрытые в ходе этой проверки

1. **Комментарий целиком на чужом письме проходил все проверки.** Гардрейл `_script_bleed` ловил
   вкрапление *внутри* русского текста, но пропускал текст, написанный целиком на китайском.
   Добавлен `script_mismatch(текст, пост)`: письмо ответа сверяется с письмом поста. Проверка
   намеренно ограничена скриптами, которые здесь не встречаются законно — латиница против кириллицы
   **не** считается ошибкой, потому что узбекская латиница под русским постом это норма (измерено:
   9 из 50 реальных пар). *Подтверждено в бою: следующие 4 генерации отклонены, в канал не ушло
   ничего.*

2. **«Ответчик» публиковал реплику союзника слово в слово.** Текст союзника приходит в
   `alpha_context`, а `is_echo` сверял только с постом. Теперь в сравнение входят и реплика
   союзника, и то, что команда уже сказала в этой ветке (`said` из досье). Блок «не повторяйся» в
   промпте остаётся, но 3B-модель инструкции игнорирует — нужна структурная проверка.

3. **Взаимоблокировка, останавливавшая весь исполнительный цикл.** При холодном кеше чтение ветки
   пыталось определить «свои» сообщения, а для этого открывало сессию того же аккаунта, чей лок
   само же и держало → «session busy» → задача вставала намертво, и вместе с ней вставал единственный
   потребитель очереди. Кеш личностей роя теперь только читается в горячем пути и прогревается один
   раз при старте, вне локов. *Подтверждено: 6 личностей прогрето за 11 с, задача больше не виснет.*

4. **Регресс от исправления №1**: проверка вызывалась как метод класса, которого у него нет —
   каждая генерация падала с `AttributeError`, задача помечалась `FAILED`. Поймано в бою, закрыто,
   добавлен тест именно на вызываемость.

На все четыре добавлены регрессионные тесты (+6 к набору).

## 6. Открытые проблемы

### Блокирующая: качество генерации

Модель — узкое место, и это измерено с трёх сторон:

| замер | результат |
|---|---|
| 4 генерации на живом посте #37 | **4 из 4 на китайском** (все отклонены новым гардрейлом) |
| 4 генерации через очередь на тестовой ветке | 2 бессмыслицы на псевдотюркском, 2 нормальных |
| 20 последних опубликованных комментариев | 4 бессмыслицы, 2 против своей же миссии, 3 с выдуманными фактами (`#КубокМира2018` под событием 2026 года), 2 с ломаными словами, 4 повтора одной фразы; приемлемых ≈ 4 |

Итог: **приемлемо примерно 20 % опубликованного**. Гардрейлы теперь превращают брак в молчание,
а не в позор, но молчание — не результат.

Три дешёвых детектора бессмыслицы проверены и отвергнуты по данным (служебные слова — 0.121 у
бессмыслицы против 0.000 у 27 настоящих англо- и узбекоязычных комментариев; идентификация языка —
`lingua` не знает узбекского и киргизского, называет бессмыслицу «славянской» с уверенностью 0.837).
Четвёртую эвристику строить не нужно — нужна модель крупнее.

### Существенные

- **Гейт релевантности пропускает рекламу.** На «Продаём квартиры в новостройке, ипотека 0%.
  Звоните!» ответил «тема прямо наша». Ложное срабатывание на явном спаме.
- **Не проверен путь живого диалога.** Наблюдения регистрируются (2 активных), но ответить боту
  может только настоящий человек: реплика с нашего же аккаунта корректно отфильтровывается как своя.
- **«После» в замере исхода ещё не снималось в бою** — по регламенту читается через 6 часов.
- **Одна цель миссии `blocked`**: `@kunuzofficial` — комментарии отключены, движок её правильно
  пропускает каждый цикл.
- **Мёртвый мобильный путь ест ресурсы**: два контейнера Android-эмуляторов (`beta_emu`,
  `test_emu`) держат **3.7 ГБ из 15.5 ГБ** и не входят в `docker-compose.yml`.

### Мелкие

- `RuntimeWarning: coroutine '_whoami_async' was never awaited` в логах MYRMIDON.
- Предупреждение `Peer id invalid: -1003930112879` при обходе каналов.
- 4 источника сбора в статусе «не проверено».

## 7. Железо и его потолок

| | |
|---|---|
| GPU | GTX 1660 Ti, 6 ГБ (свободно 5.3 ГБ) |
| RAM | 15.5 ГБ, свободно ~3.9 (из них 3.7 занимают мёртвые эмуляторы) |
| CPU | i7-10750H, 12 потоков |
| Диск | NVMe, свободно 17 ГБ (оператор готов добавить 200 ГБ) |

Что из этого следует: `gemma4:26b-a4b` (18 ГБ весов) **не помещается** — MoE экономит вычисления,
но не память. `TurboFieldfare`, который запускает её в 2 ГБ, — рантайм только для Apple Silicon
(Swift + Metal, arm64, macOS 26), у нас x86_64 + CUDA. Реальные варианты: докупить RAM (планка
32 ГБ ≈ $60–80 снимает единственный настоящий блокер и делает 26B-A4B пригодной через `llama.cpp`
с выгрузкой экспертов на CPU), либо остаться в пределах видеопамяти — `qwen2.5:7b-q4` (4.7 ГБ)
влезает уже сегодня.

## 9. Что делать дальше, по приоритету

1. **Сравнить `qwen2.5:7b-q4` с `qwen2.5:3b` в полигоне** на одном и том же импортированном треде.
   Это единственный способ узнать, сколько качества даёт размер, до любых покупок. Модель влезает в
   текущую видеопамять.
2. **Погасить `beta_emu` и `test_emu`** — освободить 3.7 ГБ, ничего не сломав.
3. **Починить гейт релевантности на рекламе** — добавить рекламные признаки в `textutil` и
   проверить на подборке реальных объявлений.
4. **Проверить диалог с живым человеком** — оператору написать ответ боту под его комментарием;
   всё остальное для многоходового разговора уже готово и ждёт собеседника.
5. **Планка RAM 32 ГБ**, если целимся в `gemma4:26b-a4b` — тогда же перевести генерацию с Ollama на
   `llama.cpp` (`-ot exps=CPU`), потому что Ollama не даёт управлять выгрузкой экспертов.

## 10. Как воспроизвести замеры

```bash
# тесты
docker compose exec orpheus  python -m pytest tests -q     # 75
docker compose exec myrmidon python -m pytest tests -q     # 29
docker compose exec daedalus python -m pytest tests -q     # 58

# метрики корпуса и роя
docker compose exec postgres psql -U morpheus_admin -d morpheus_db -c \
  "select count(*), round(avg(length(content))) from knowledge_facts;"
docker compose exec postgres psql -U morpheus_admin -d morpheus_db -c \
  "select status, count(*) from agent_activity_logs group by status;"

# качество опубликованного — та самая выборка
docker compose exec postgres psql -U morpheus_admin -d morpheus_db -c \
  "select left(text_content,110) from agent_activity_logs
   where status='SUCCESS' and action_type='comment' order by created_at desc limit 20;"

# боевой цикл (публикует в реальный канал!)
# 1) вывести миссию в работу в UI  2) сбросить отметку последнего поста:
docker compose exec redis redis-cli HSET morpheus:target:lastseen "mission:10:@tashkent_news333" <id-1>
```
